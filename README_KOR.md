# janusline

[![CI](https://github.com/oh-namgyu/janusline/actions/workflows/ci.yml/badge.svg)](https://github.com/oh-namgyu/janusline/actions/workflows/ci.yml)

셀프호스트 **양면 뉴스 브리핑** 도구. 검색어 하나 — 기업, 인물, 이슈 — 를 넣으면
janusline 이 그 주변 뉴스를 수집해 하나의 세로 타임라인에 배치합니다.
**우호적 보도는 왼쪽, 비우호적 보도는 오른쪽**, 시간순으로, 중립 기사는 가운데
레일에. 그 아래에는 같은 재료로 쓴 **두 개의 대립하는 해석**을 나란히 놓습니다.
각각 *이 해석이 맞다면* 이라는 명시적 IF 시나리오와, 그 해석이 기대고 있는 기사에
대한 인용을 함께 답니다.

목적은 누가 옳은지 알려주는 것이 아닙니다. 피드가 건네준 쪽이라는 이유만으로
한쪽 서사만 읽게 되는 것을 막는 것입니다.

모든 데이터는 내 컴퓨터의 평범한 파일로 남습니다. API 키 하나(그마저 선택),
DB 없음, 계정 없음, 빌드 단계 없음.

## 고지 — 먼저 읽어주세요

**janusline 은 보조 리서치 도구이지 사실검증 도구가 아닙니다.**

- **분석은 자동 생성물입니다.** 감정 라벨, 한 줄 요약, 두 서사와 두 IF 시나리오는
  전부 언어 모델이 씁니다. 검증된 결론이 아니라 자동화된 해석이며, 틀릴 수 있습니다.
- **기사가 아니라 헤드라인을 읽습니다.** 가져오는 것은 RSS 제목과 피드 스니펫뿐
  입니다. 기사 전문은 절대 수집하지 않으므로, 모든 판정은 제목과 한두 문장만 보고
  내려집니다 — 원문을 열어보면 분류가 뒤집힐 수 있습니다.
- **"긍정"과 "부정"은 *검색한 주체에게* 유리한지를 뜻하며**, 기사의 문체를 뜻하지
  않습니다. 중립적으로 쓰인 리콜 공지는 부정이고, 경쟁사의 악재는 긍정입니다.
  이는 의도된 정의이며, 동시에 모델이 틀릴 수 있는 판단입니다.
- **출처를 여세요.** 모든 카드가 원문으로 연결됩니다. 앱은 모든 브리핑에 이 문구를
  표시하고, 내보낸 파일도 각주에 같은 말을 반복합니다. 두 문구 모두 모델이 고쳐 쓸
  수 없습니다 — 서버가 소유한 문장입니다.
- **인물이나 기업에 대한 근거로 쓰지 마세요.** 실명을 검색해 오른쪽 열을 사실로
  받아들이는 것이야말로 이 절이 경고하려는 오용입니다.

## 동작 방식

```
검색어
      │
      ▼
  Collect ──► 기사                              (API 호출 0회 — 공개 Google News RSS)
      │        한국어 + 영어 에디션, 중복 제거, 기간 필터, 최대 40건
      ▼
  Analyze ──► 감정 · 요약 · 근거구절             (분류 호출 ⌈n/25⌉회)
      │    ──► 두 해석 + IF 시나리오             (+ 종합 호출 1회)
      ▼
  Read ──► 이중 타임라인 + 두 해석               (0회 — 파일 읽기일 뿐)
      │
      ▼
  Export ──► 스크립트도 외부 참조도 없는 단일 standalone HTML 파일
```

수집과 분석이 별도 버튼인 것은 의도된 것입니다. 수집은 무료이므로, 그 검색어가
실제로 무엇을 물어오는지 보고 — 검색어가 잘못됐다고 판단할 기회를 가진 뒤 —
분석에 비용을 치를 수 있습니다.

두 가지 그라운딩 규칙이 결과물을 출처에 묶어 둡니다. `evidence` 인용구는 해당
기사 자신의 제목이나 스니펫에 **그대로 존재하는 부분 문자열**일 때만 유지되며,
말을 바꾼 것은 *no direct quote* 로 강등되고 분류 자체는 남습니다. 해석의
`citations` 는 **실제로 보낸 기사 id** 여야 하며, 한쪽이 아무것도 인용하지 못하면
UI 는 이를 근거 있는 것처럼 보여주지 않고 *insufficient citations* 로 표시합니다.

## 빠른 시작

### 로컬 (venv)

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...      # 선택 — 분석 전용
python app.py
```

<http://127.0.0.1:6181> 을 여세요. JSON API 는 `/api` 아래에 있습니다.

**키가 없어도 동작합니다.** 브리핑 생성, 뉴스 수집, 타임라인 열람, 내보내기는
키 없이 전부 됩니다. 키가 필요한 것은 *Analyze* 뿐이고, 키가 없으면 그 호출만
`503` 을 돌려줍니다. Google News RSS 는 공개 피드입니다.

분석까지 포함해 전부 오프라인으로 보고 싶다면 `JANUSLINE_FAKE=1 python app.py` 가
픽스처 피드와 오프라인 분석기를 끼워 넣습니다 — 키도, 네트워크도, 비용도 없습니다.

### Docker

```bash
cp .env.example .env        # AUTH_TOKEN 을 채우세요 (분석을 원하면 ANTHROPIC_API_KEY 도)
mkdir -p data && sudo chown 10001:10001 data
docker compose up -d
```

컨테이너는 자기 네트워크 네임스페이스 안에서 `0.0.0.0` 에 바인드하므로
**`AUTH_TOKEN` 이 필수**입니다 — 토큰이 없으면 바인드 가드가 종료 코드 1 로 죽고,
compose 는 그 전에 기동을 거부합니다. compose 는 호스트의 `127.0.0.1:6181` 로만
포트를 매핑하므로, 그 줄을 직접 바꾸기 전까지는 네트워크에 아무것도 노출되지 않습니다.

## 설정

모든 설정은 환경변수입니다. [.env.example](.env.example) 을 보세요.

| 변수                    | 기본값            | 의미                                                             |
|-------------------------|-------------------|------------------------------------------------------------------|
| `ANTHROPIC_API_KEY`     | _(미설정)_        | 선택. 분석 전용. 없으면 `/analyze` → `503`, 수집과 열람은 영향 없음. |
| `AUTH_TOKEN`            | _(미설정)_        | 토큰 로그인 활성화. **루프백이 아닌 바인드에는 필수.**             |
| `HOST`                  | `127.0.0.1`       | 바인드 주소.                                                      |
| `PORT`                  | `6181`            | HTTP 포트.                                                        |
| `JANUSLINE_MODEL`       | `claude-sonnet-5` | 분류와 종합에 쓰는 텍스트 모델.                                    |
| `JANUSLINE_DATA`        | `./data`          | `briefs/<slug>/` 와 삭제된 브리핑 휴지통의 루트.                   |
| `JANUSLINE_TRASH_DAYS`  | `7`               | 기동 시 휴지통 브리핑을 비우는 기준 일수.                          |
| `JANUSLINE_FAKE`        | _(미설정)_        | `1` 이면 오프라인 픽스처 피드와 오프라인 분석기로 교체 (데모/테스트). |

브리핑별 옵션은 UI 에서 정합니다: **기간**(30 / 90 / 365일, 기본 90)과
**에디션**(한국어, 영어, 또는 둘 다 — 기본 둘 다).

## 비용

**janusline 은 사용자 본인의 API 크레딧을 씁니다.** 서비스가 아니며 자체 과금이
전혀 없습니다 — 사용자가 준 키로 Anthropic 을 호출하고, 요금은 Anthropic 에 공시된
요율로 직접 지불합니다.

| 작업                                  | API 호출                                                                  |
|---------------------------------------|---------------------------------------------------------------------------|
| **수집(Collect)**                     | **0회** — Google News RSS 는 공개 피드. 키도 비용도 없고, 에디션당 HTTP 요청 1회. |
| **분석(Analyze)**                     | ⌈기사수 ÷ 25⌉ 회의 분류 호출 **+ 1회**의 종합 호출. 40건 상한에서 **3회**.  |
| 열람 · 재조회 · 내보내기 · 삭제        | **0회** — 이 작업들은 내 컴퓨터를 떠나지 않습니다.                          |

응답이 스키마 검증에 실패한 호출은 오류를 되짚어 주며 **정확히 한 번** 재시도하므로,
운이 최악인 분석도 포기하기 전까지 최대 2배를 넘지 않습니다. 출력은 호출당
8192 토큰으로 제한됩니다. 재분석은 전체 세트를 다시 돌리며, 그 전에 다시 수집하는
것은 무료입니다.

## 프라이버시

- **밖으로 나가는 것:** 검색어가 RSS 쿼리 문자열로 Google News 에 갑니다.
  *Analyze* 시에는 검색어와 수집된 **헤드라인 · 피드 스니펫**이 Anthropic API 로
  갑니다. 외부로 나가는 트래픽은 이것이 전부입니다.
- **나가지 않는 것:** **텔레메트리, 애널리틱스, 크래시 리포팅, 업데이트 확인이
  전혀 없습니다.** janusline 은 그 밖의 어떤 네트워크 호출도 하지 않습니다. 기사
  링크는 저장·표시되지만 **절대 fetch 하지 않습니다** — 링크를 여는 것은 서버가
  아니라 사용자의 브라우저입니다.
- **데이터가 있는 곳:** 내 디스크의 `data/briefs/<slug>/brief.json` 평문 JSON.
  삭제된 브리핑은 `data/.trash/` 로 옮겨져 7일 뒤 비워집니다. 어디에도 업로드되지
  않습니다.
- **API 키**는 서버 환경변수에서만 읽습니다. 디스크에 쓰이거나, 응답에 담기거나,
  로그에 남는 일이 없습니다.
- Google 과 Anthropic 은 각자의 데이터 취급 정책을 보낸 내용에 적용합니다. 검색어
  자체가 민감할 수 있으니, 민감한 것을 검색하기 전에 그 정책들을 확인하세요.

## 보안 모델

janusline 은 **단일 사용자 · 셀프호스트** 도구입니다.

- **기본은 루프백.** `HOST=127.0.0.1`, Docker 에서는 compose 포트 매핑.
- **안전하지 않은 노출은 거부.** `AUTH_TOKEN` 없이 루프백이 아닌 주소에 바인드하면
  경고가 아니라 기동 실패입니다.
- **노출 시 토큰 로그인.** `AUTH_TOKEN` 을 켜면 로그인 폼, 상수시간 토큰 비교,
  그리고 8시간 수명의 HMAC 서명 `httpOnly` / `SameSite=Strict` 세션 쿠키가
  활성화됩니다. 변이 요청은 same-origin `Origin`/`Referer` 게이트를 추가로 통과해야
  합니다.
- **자체 TLS 없음.** 트래픽은 평문 HTTP이며, 루프백이 아닌 바인드는 그렇다고 경고를
  출력합니다. 무엇에든 노출하기 전에 TLS 종단 리버스 프록시 뒤에 두세요.
- **고정 호스트 fetch.** 서버가 접촉하는 유일한 호스트는 `news.google.com` 입니다.
  검색어는 URL 인코딩되어 쿼리 문자열에 들어갈 뿐 호스트를 결정하지 않으므로 SSRF
  표면이 없고, 기사 링크는 따라가지 않습니다.
- **신뢰할 수 없는 피드 텍스트.** 헤드라인과 스니펫은 제3자 입력입니다. 스스로
  닫을 수 없는 명시적 데이터 블록으로 감싸고, 두 시스템 프롬프트 모두 그 안의
  지시는 무시하라고 지정하며, 경로 전체를 `innerHTML` 이 아닌 `textContent` 로
  렌더합니다.
- **의도된 단일 워커.** 브리핑 쓰기는 인프로세스 락으로 직렬화되므로
  gunicorn/uwsgi 다중 워커 배포는 지원되지 않으며 동시 쓰기를 손상시킵니다. Docker
  이미지는 의도적으로 프로세스 하나만 돌립니다.

전체 위협 모델: [SECURITY.md](SECURITY.md).

## 결과물 공유

*Export* 는 **단일 standalone HTML 파일**을 만듭니다 — 타임라인 양쪽 열, 두 해석,
고지 문구, 모든 출처 링크를 담고, 스타일시트는 인라인이며, 스크립트 0개 · 외부
참조 0개입니다. `file://` 에서 오프라인으로 바로 열리고, 인쇄됩니다. 남에게
건네는 단위는 그 파일 하나입니다. janusline 자체는 단일 사용자용이므로, 공유란
실행 중인 인스턴스를 공유하는 것이 아니라 내보낸 파일을 공유하는 것입니다.

## 개발

```bash
pip install -r requirements-dev.txt
playwright install chromium      # 브라우저 테스트용, 한 번만

python -m pytest -q              # 단위 테스트 — 네트워크도 키도 없음
python -m pytest e2e -q          # 실제 서버를 띄우는 브라우저 왕복

python scripts/preflight.py      # 실 RSS 엔드포인트 확인 (키가 있으면 모델까지)
```

단위 테스트는 네트워크도 API 키도 필요 없습니다. 수집기 테스트는 `fetch()` 만
스텁한 채 **실제** 파싱 파이프라인을 저장된 피드 픽스처 위에서 돌리고, 분석기는
스크립트된 스텁입니다. e2e 는 임시 데이터 디렉토리에 `JANUSLINE_FAKE=1` 로 실제
`app.py` 를 띄우며, chromium 이 없으면 실패가 아니라 **skip** 합니다.

`JANUSLINE_FAKE=1` 은 UI · 플로우 게이트이지 분석 품질 게이트가 아닙니다 — 왕복이
동작함을 증명할 뿐, 실제 모델이 잘 분류함을 증명하지는 않습니다.

컨벤션: 파일은 300줄 이하, 모든 스타일은 전역 `static/style.css` 에(인라인 스타일
금지), 사용자·LLM 유래 문자열은 `textContent` 로만 주입.
[CONTRIBUTING.md](CONTRIBUTING.md) 를 보세요.

## 한계

- **비공식 피드 의존.** Google News RSS 는 문서화된 지원 API 가 아닙니다. 예고 없이
  형식이 바뀌거나 요청을 거부하기 시작할 수 있고, 호소할 계약이 없습니다. 수집은
  어댑터 하나(`core/collect.py`)에 격리되어 픽스처 테스트를 갖고 있으므로 형식
  변경은 재작성이 아니라 작은 수정입니다 — 그래도 여전히 단일 실패점입니다.
- **스니펫만으로의 그라운딩.** 분류도 두 해석도 헤드라인과 피드 스니펫만 봅니다.
  전문은 저작권과 `robots.txt` 를 이유로 의도적으로 수집하지 않으며, 이것이 여기서
  내릴 수 있는 판정의 정확도 상한입니다. 고쳐야 할 버그가 아니라 제품 전체의
  천장입니다.
- **모호한 검색어는 중립으로 강등됩니다.** 일반명사나 동명이인은 모델이 주체와 묶을
  수 없는 기사를 만들어내며, 그런 기사는 추측 대신 근거 없는 *neutral* 이 됩니다.
  중립이 대부분인 브리핑은 보도가 균형 잡혔다는 뜻이 아니라 검색어를 좁혀야 한다는
  뜻인 경우가 많습니다. 본격적인 엔티티 해소는 구현되어 있지 않습니다.
- **에디션 2개, 감정 3종.** 한국어와 영어뿐이고, 긍정 / 부정 / 중립뿐입니다. 다른
  로케일도, 더 세분화된 척도도, 토픽 클러스터링도 없습니다.
- **분량 상한.** 브리핑당 기사 40건(에디션당 20건), 기간 30 / 90 / 365일, 검색어
  200자 이하. 페이지네이션도 아카이브도 없습니다 — 브리핑은 스냅샷이며, 다시
  수집하면 교체됩니다.
- **단일 프로세스 · 단일 사용자.** 계정도 역할도 사용자별 데이터도 없습니다.
  `AUTH_TOKEN` 하나를 건네받은 사람 모두가 공유하고, 인프로세스 락 때문에 워커는
  하나입니다.
- **레이트 리밋 없음.** 수집이나 분석을 제한하는 장치가 없습니다. 공유된 토큰은
  공유된 지출 한도입니다.
- **TLS 없음, 다국어 UI 없음.** UI 는 영어입니다. 한국어와 영어로 오는 것은 *기사*
  뿐입니다.
